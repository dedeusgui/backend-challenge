# Documentation conventions

> English reference copy. The main version, in Portuguese, is [CONVENCOES_DOCUMENTACAO.md](CONVENCOES_DOCUMENTACAO.md).

These rules apply to all documentation. The documentation is part of the grading (section 14 of the
[specification](CHALLENGE.md)), so every change to it follows the same workflow.

## Language and English pairs

- The **main version is in Portuguese (pt-BR)**. It is the one the evaluator reads first.
- Each main document has an **English reference copy**, with the suffix `.en.md`, like the pair
  [README.md](../README.md) and [README.en.md](../README.en.md). Examples: `ARCHITECTURE.md` and `ARCHITECTURE.en.md`,
  `DECISIONS.md` and `DECISIONS.en.md`, `docs/adr/0001-pessimistic-wallet-lock.md` and its `.en.md`.
- The English copy points to the Portuguese version at the top, and its internal links point to the English copies.
- **When you change a document that has a pair, update both in the same commit.** The Portuguese version is the source of truth.

## File names do not change

Code, tests, scripts and `CLAUDE.md` point to fixed paths. Do not rename or move these files without updating every
reference: `ARCHITECTURE.md`, `DECISIONS.md`, `docs/REQUIREMENTS_MATRIX.md`, `docs/LOAD_TEST_RESULTS.md`,
`docs/CHALLENGE.md`, `docs/adr/*.md`, `docs/audit/*.md` and `CLAUDE.md`.

## What is not translated

- Code, commands, paths, class names, JSON field names and environment variable names.
- Requirement, decision and test IDs (for example `TX-02`, `ELIM-08`, `E-01`, `R-13`).
- Matrix status tokens: `PASSING`, `PASS`, `BLOCKED`. Tools read those values.
- Numbers in the source format. Use a decimal point (`100.00`) and a comma thousands separator (`1,153`), as in the
  code and the measurements. Do not convert them to the Brazilian format, because mixing the two confuses the reader.

## Generated documents: do not edit by hand

- [LOAD_TEST_RESULTS.md](LOAD_TEST_RESULTS.md) is generated by `test/load/report.ts`. Any edit is overwritten by the
  generator. The file remains in English, as emitted by the generator.
- `docs/load/`, `docs/edge/results/` and `docs/audit/perf/` are raw measurements in JSON.
- `docs/site/` is the source of the static site. Build it with `bun run site:build`.

## Indexes that must follow the changes

- [docs/README.md](README.md): the central index, the evaluator questions and the main reading path. Update it when a
  document is created, removed or changes role.
- [DECISIONS.md](../DECISIONS.md): the consolidated index of decisions, by group. A new decision goes into the right
  group, and the index count is updated. If it has an ADR, the ADR is also created or updated.
- [docs/adr/README.md](adr/README.md): the ADR index. A superseded ADR keeps its file, with a supersession note at the top.

## Every claim of proof points to something that exists

- A relative link must point to an existing file.
- A cited test path must exist.
- A cited command must exist in `package.json`.
- A requirement can be `PASSING` only after the suite that proves it has run and passed.
- A claim that the evidence contradicts is corrected. When the history matters, the old text keeps a supersession
  note, and is not deleted.

## Workflow for a documentation change

1. **Scope:** say what changes and what does not. A documentation-only change does not alter code.
2. **Translation or drafting:** it can be done by an Orca worker, with a clear contract (allowed file, what must not
   change, and acceptance criteria). Low-cost models fit this: Codex `gpt-6-luna` at low effort, or Antigravity
   `gemini-3.8-flash-low`. Choose the Antigravity ID with `agy models`.
3. **Review:** compare the file with the original version (`git show HEAD:<file>`). Code blocks, links, tables,
   numbers, IDs and status tokens must be the same. Read a sample of the text, because the automatic check does not
   catch a badly translated sentence.
4. **Formatting:** `bunx prettier --write <files>`. Tables are realigned, so format before you check.
5. **Verification:** `bun run check:fast`, which includes `format:check` and the tests that read the matrix and the site.
   Before closing the slice, `bun run check:all`, which requires `bun run infra:up`. Then stop the infrastructure with
   `docker compose down`.
6. **Commit:** one Conventional Commit, for example `docs: ...`, with a body that describes the change.
