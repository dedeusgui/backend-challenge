# Glossário do domínio

Termos do enunciado e do código, em português. Identificadores técnicos (nomes de classes, valores de enum,
campos JSON) não são traduzidos, porque é assim que aparecem no código e no contrato.

| Termo                                         | Significado                                                                                                                                                                                                                                 |
| --------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Provedor** (`providerId`)                   | Fornecedor de jogos que envia operações. Uma chave PROVIDER age só pelo próprio provedor.                                                                                                                                                   |
| **Operador**                                  | Papel de back office, com chave OPERATOR: abre e lê carteiras, reconcilia, lê métricas e age por qualquer provedor.                                                                                                                         |
| **Carteira** (`Wallet`)                       | Saldo de um jogador numa moeda. Uma por `playerId` e moeda. É a unidade de concorrência.                                                                                                                                                    |
| **Versão** (`version`)                        | Número da carteira. Começa em 1 e sobe uma vez por alteração de saldo. Não sobe por `LOSS`.                                                                                                                                                 |
| **Operação** (`WagerTransaction`)             | Uma ação enviada por um provedor: aposta, ganho, perda, reembolso ou rollback. Tem um id interno e um `externalTransactionId` do provedor.                                                                                                  |
| **Tipo** (`kind`)                             | `OPENING` (interno, abertura da carteira), `BET`, `WIN`, `LOSS`, `REFUND`, `ROLLBACK`.                                                                                                                                                      |
| **Aposta** (`BET`)                            | Débito de um valor da carteira. Recusada se o saldo não cobre.                                                                                                                                                                              |
| **Ganho** (`WIN`)                             | Crédito. Pode nomear a `BET` que liquida, mas o enunciado não obriga.                                                                                                                                                                       |
| **Perda** (`LOSS`)                            | Registra o resultado sem mover saldo, e sem lançamento no ledger.                                                                                                                                                                           |
| **Reembolso** (`REFUND`)                      | Crédito que devolve a aposta. Só reverte uma `BET` sem resultado, uma única vez.                                                                                                                                                            |
| **Rollback** (`ROLLBACK`)                     | Reverte uma `BET`, um `WIN` ou um `REFUND` já processado, uma única vez, no valor exato.                                                                                                                                                    |
| **Referência**                                | A operação anterior que `REFUND` ou `ROLLBACK` reverte, por `referenceExternalTransactionId`.                                                                                                                                               |
| **Estado** (`status`)                         | `PENDING` (aceita), `PENDING_REFERENCE` (aguardando a referência), `PROCESSED` (aplicada), `REJECTED` (recusada por regra), `FAILED` (falha permanente; não alcançável no caminho atual). `PROCESSED`, `REJECTED` e `FAILED` são terminais. |
| **Retenção**                                  | Estado `PENDING_REFERENCE`: a operação espera a referência, com retentativas e backoff, até seis tentativas.                                                                                                                                |
| **Código de falha** (`failureCode`)           | Motivo estável e legível por máquina de uma recusa, como `INSUFFICIENT_BALANCE`. Lista em ARCHITECTURE §3.                                                                                                                                  |
| **Saldo observado** (`resultingBalance`)      | O saldo no instante em que a operação chegou ao estado atual. Um replay devolve esse valor, não o saldo atual.                                                                                                                              |
| **Replay** (`idempotentReplay`)               | Mesma chave e mesmo payload: a resposta original, com HTTP 200. Não aplica nada de novo.                                                                                                                                                    |
| **Conflito de idempotência**                  | Mesma chave com payload diferente. Responde 409, nunca replay.                                                                                                                                                                              |
| **Chave de idempotência** (`Idempotency-Key`) | Obrigatória na submissão. Fonte da verdade da idempotência, por provedor.                                                                                                                                                                   |
| **Liquidação** (`TransactionSettlement`)      | A decisão financeira: aplica, recusa ou retém uma operação. Única implementação, usada pela HTTP e pelo worker.                                                                                                                             |
| **Lançamento** (`WalletLedgerEntry`)          | Linha imutável do ledger: direção, valor, saldo antes e depois. Uma por carteira e transação, no máximo.                                                                                                                                    |
| **Ledger**                                    | A sequência de lançamentos de uma carteira. Seu somatório é o saldo, e a reconciliação compara os dois.                                                                                                                                     |
| **Reconciliação**                             | Recalcula o saldo pelo ledger e informa divergência. Só lê; nunca corrige.                                                                                                                                                                  |
| **Divergência**                               | Diferença entre o saldo armazenado e o calculado. Deve ser informada, nunca escondida.                                                                                                                                                      |
| **Inbox**                                     | Registro de mensagem recebida, por `(consumidor, messageId)`. Deduplica a entrega. Gravado na transação do efeito.                                                                                                                          |
| **Outbox**                                    | Registro do evento de integração, gravado na mesma transação do efeito. Só é publicado depois do commit.                                                                                                                                    |
| **Lease** (publicador)                        | Reserva temporária de um lote do outbox por um publicador, com token. Expira, e outro publicador pode assumir.                                                                                                                              |
| **`eventId`**                                 | Identificador estável de um evento. É a chave de deduplicação do consumidor e o id de deduplicação do SQS.                                                                                                                                  |
| **`walletVersion`**                           | Versão da carteira no evento `WalletBalanceChanged`. É a chave de ordem de um consumidor para as alterações de uma carteira.                                                                                                                |
| **DLQ** (`wager-transactions-dlq.fifo`)       | Fila de mensagens com falha permanente, ou que excederam as tentativas. Não é reprocessada automaticamente.                                                                                                                                 |
| **Commit e ACK**                              | A mensagem SQS só é confirmada depois do commit da transação. Antes, uma morte gera reentrega, e a inbox impede o segundo efeito.                                                                                                           |
| **At-least-once**                             | Garantia de entrega: todo evento chega, possivelmente mais de uma vez. O consumidor deduplica.                                                                                                                                              |
| **Escopo de provedor**                        | Regra que impede uma chave de agir pelo id de outro provedor. Aplicada antes de qualquer escrita.                                                                                                                                           |
| **Modo protegido**                            | Stack com borda Nginx que limita por endereço de cliente. Não é proteção contra ataque distribuído.                                                                                                                                         |
